# 08 技术方案（Unity）

## 1. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 引擎 | Unity 6.3 LTS（6000.3.x），2D（URP） | 用户指定；2D 管线 + Shader Graph 足够做翻面扭曲、癫狂后处理 |
| 语言 | C# 9（Unity 当前的语言版本上限） | 内核代码不要用更新的语法，这样也能在 .NET 外部工程里编译 |
| UI | UGUI + TextMeshPro | 卡牌需要频繁做动画和层级排序，UGUI 比 UI Toolkit 更成熟 |
| 补间动画 | DOTween（免费版）或 PrimeTween | 二选一；PrimeTween 零 GC 分配，API 也更现代 |
| 异步编排 | UniTask（或 Unity 6 内置的 `Awaitable`） | 表现层按顺序播放动画 |
| 序列化 | Newtonsoft JSON（`com.unity.nuget.newtonsoft-json`） | 存档、遥测 |
| 输入 | Input System | |
| 测试 | Unity Test Framework（EditMode）+ 外部 `dotnet test` | 见 §7 |
| 版本控制 | Git + Git LFS（美术、音频） | 项目目录目前还不是仓库，阶段 1 开始时初始化 |

## 2. 总体架构：逻辑与表现分离

```
┌──────────────────────── Game.Core（纯 C#，noEngineReferences）────────────────────────┐
│  RunState ── MapGen ── Rewards ── Shop/Events                                          │
│     │                                                                                  │
│  BattleState ◀── ActionQueue ◀── Cards / Statuses / Relics / EnemyAI（触发器）           │
│     │                 │                                                                │
│     │                 └──▶ BattleEventLog（结构化事件流：DamageApplied、SanityChanged…） │
└─────┼──────────────────────────────────┼───────────────────────────────────────────────┘
      │ 只读查询                          │ 按顺序消费
┌─────▼──────────────────────────────────▼─────── Game.View（MonoBehaviour）──────────────┐
│  BattleDirector：逐条播放事件 → 卡牌动画 / 飘字 / 意图刷新 / 翻面 / 后处理                  │
│  HandView、CardView、EnemyView、IntentView、MapView …                                   │
│  输入 → 生成 PlayerCommand（PlayCard / UsePotion / EndTurn / ChooseOption）→ 交给 Core    │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

**原则**

1. Core 程序集勾选 `noEngineReferences`，**不能引用 UnityEngine**，在编译层面保证逻辑和表现分离
2. 逻辑**瞬时结算**，产出事件流；表现层**按顺序回放**。这样模拟器可以不带任何动画地全速运行
3. 表现层**只读** Core 的状态，所有修改都通过 `PlayerCommand` 进入 Core

## 3. 战斗内核

### 3.1 动作队列

参照尖塔的 `addToBottom / addToTop` 模型：所有游戏效果都封装成 `GameAction` 入队，触发器（状态、遗物、能力）把新动作插队到队首。

```csharp
public abstract class GameAction
{
    // 返回 false 表示需要玩家输入（如「选 1 张弃掉」），队列挂起
    public abstract bool Execute(BattleContext ctx);
}

public sealed class ActionQueue
{
    private readonly LinkedList<GameAction> _list = new();
    public void AddToBottom(GameAction a) => _list.AddLast(a);
    public void AddToTop(GameAction a) => _list.AddFirst(a);

    // 一直执行到队列为空，或者遇到需要输入的动作
    public QueueResult Process(BattleContext ctx) { /* ... */ }
}
```

需要玩家做选择的效果（弃牌、发现、心灵之锚的二选一）会让 `BattleState.Phase = WaitingForChoice`。表现层弹出选择 UI，玩家选完后发出 `ChooseOption` 命令，队列继续执行。

### 3.2 事件总线（逻辑层）

```csharp
// 触发点：OnCombatStart, OnTurnStart, OnTurnEnd, OnCardPlayed, OnDamageDealt,
//         OnSanityChanged, OnLunacyChanged, OnCollapse, OnEnemyStunned, OnEnemyDeath ...
public interface IBattleListener { int Priority { get; } }
```

状态、遗物、能力都实现自己需要的接口，比如 `IOnSanityChanged`。分发时按 `Priority` 排序，保证「先加后乘」等修正顺序是确定的。

### 3.3 修正管线

伤害、格挡、理智变化都走统一的 `ModifierPipeline`。每个修正器声明自己所在的阶段（Add / Multiply / Final），结算顺序严格按照 [02 §3](02_战斗系统.md) 的公式。卡面上的「预览数值」也调用同一条管线（传入 `preview = true`，不产生副作用），保证卡面显示的数字和实际结算的一致。

### 3.4 理智状态机

```csharp
public sealed class SanityComponent
{
    public int Current, Max;
    public bool IsLunatic => Current <= Config.LunacyThreshold;   // 4
    public bool IsClarity => Current == Max;
    // Lose / Restore 内部：心防判定 → 变更 → 发出 SanityChanged
    //   若 IsLunatic 发生变化 → 发出 LunacyChanged → 双面牌刷新、意图模糊开关
    //   若 Current == 0 → 入队 CollapseAction
}
```

### 3.5 敌人 AI

`EnemyBehaviour` 持有招式表 `MoveTable`；每回合按 [02 §6.2](02_战斗系统.md) 的四步选出下一招，结果写进 `EnemyState.Intent`。Boss 的阶段和潮位用敌人自身的 `Counter` 字典保存。

## 4. 内容数据管线

**方案：卡牌逻辑写在 C# 类里，数值和文本放在 CSV 表里。**

这是尖塔原作的做法（每张牌一个类，再加 baseDamage / magicNumber 字段），在灵活度和可调参性之间取了平衡：

- 逻辑复杂的牌（旧日注视、圣痕）写代码最直接，不需要设计一套复杂的效果 DSL
- 数值全部在表里，调参不用改代码，也方便批量对比

```csharp
[CardId("C06")]
public sealed class NightmareBlade : CardBase
{
    public override void OnPlay(BattleContext ctx, Target t)
    {
        if (ctx.UsesMadFace(this))   // 卡面在出牌第一步锁定，见 02 §3.5
        {
            ctx.Queue.AddToBottom(new DamageAction(t, V["MadDamage"]));
            ctx.Queue.AddToBottom(new LoseHpAction(ctx.Player, V["SelfHp"]));
        }
        else ctx.Queue.AddToBottom(new DamageAction(t, V["Damage"]));
    }
}
```

`Data/cards.csv`：

```
id,name,type,rarity,archetype,cost,cost_up,target,dual,keywords,keywords_up,vars,vars_up,text_sane,text_mad,text_sane_up,text_mad_up
C06,梦魇之刃,Attack,Common,堕落,1,,Enemy,1,,,Damage=8;MadDamage=13;SelfHp=2,Damage=10;MadDamage=17,造成 {Damage} 伤害。,造成 {MadDamage} 伤害，失去 {SelfHp} 生命。,,
```

> 实现（2026-10-18）：类的注册用显式的「ID → 工厂」表（`CardClasses`、`EnemyClasses`、`RelicClasses`、`PotionClasses`、`EventClasses`），不用 `[CardId]` 特性加反射扫描，避免 IL2CPP 打包时被代码裁剪。Core 只接收 CSV 字符串（`GameData.Load`），读文件交给外层：Unity 用 TextAsset，Tools 读磁盘。校验错误一次性列出，载入失败时保留旧数据

- 敌人（`enemies.csv`：生命、意志、招式数值）、遗物、药水、事件都用同样的模式
- 启动时做一次校验：每个 CSV 行都要有对应的类，文本里的 `{变量}` 都要在 `vars` 里定义；校验失败直接报错
- 文本统一走 key，以后接入 Unity Localization 做多语言时不用改结构
- 美术资源映射（卡图、敌人立绘）放在 ScriptableObject 的 `ArtDatabase` 里，Core 只认 ID

## 5. 随机数

使用自己实现的 PCG32 或 xorshift128+（**不用 `System.Random`**，它的实现可能随运行时版本变化，无法保证可复现）。

| 随机流 | 用途 |
|---|---|
| `mapRng` | 地图生成 |
| `encounterRng` | 遭遇抽取 |
| `rewardRng` | 卡牌 / 遗物 / 药水奖励 |
| `shuffleRng` | 洗牌（每场战斗用 种子 + 层数 派生） |
| `aiRng` | 敌人选招 |
| `eventRng` | 事件抽取和事件内部的随机 |
| `miscRng` | 随机目标、随机弃牌等 |

各个流互相独立：多看一次奖励不会改变后面的地图或敌人行为，这对复现 bug 和平衡测试都很关键。

> 实现（2026-10-18）：局层 6 条流 `Map`、`Encounter`、`Reward`、`Shop`、`Event`、`Misc`（`RunState`）；每场战斗的种子 = `Pcg32.Mix(局种子, 已打战斗数)`，战斗内部再分 `Shuffle`、`Ai`、`Misc` 三条（`BattleRng`）。战斗里怎么打都不会影响局层的随机结果

## 6. 存档

- `RunState` 序列化为 JSON：种子、各随机流的状态、地图、当前层、牌组（ID + 是否升级）、遗物、药水、金币、生命、理智上限、删卡次数
- 进入节点、战斗结束（奖励界面）、回到地图时写入 `Application.persistentDataPath/run.json`；先写临时文件再改名替换，防止写到一半损坏。Core 只产出纯数据快照，JSON 读写在外层（Tools 的实现是 `Tools/Shared/RunSaves.cs`，Newtonsoft）
- 战斗中途不存档：读档后回到这场战斗的开始，战斗种子不变，所以起手和首回合意图完全相同
- 存档里带 `version` 字段，以后改结构时用迁移函数升级旧存档

## 8. 目录结构

```
自制游戏/
├─ 策划/                         ← 本文档
├─ 原型/                         ← 阶段 0 纸面原型（HTML 源文件 + 打印用 PDF）
├─ Deeptide/                     ← Unity 工程
│  ├─ ArtSource/                 ← 美术源文件（LFS，不进 Assets，见 10 §11.5）
│  └─ Assets/_Project/
│     ├─ Scripts/
│     │  ├─ Core/                ← Game.Core.asmdef（noEngineReferences）
│     │  │  ├─ Battle/  Actions/  Statuses/  Cards/  Enemies/  Relics/
│     │  │  ├─ Run/     Map/      Random/     Data/（CSV 解析）
│     │  ├─ View/                ← Game.View.asmdef
│     │  │  ├─ Battle/  Map/  Shop/  Common/
│     │  └─ Editor/              ← 数据校验、卡牌预览窗口
│     ├─ Data/                   ← cards.csv、enemies.csv、relics.csv …
│     ├─ Art/  Audio/  Prefabs/  Shaders/
│     └─ Scenes/                 ← Boot、MainMenu、Run
└─ Tools/                        ← .NET 10，Deeptide.slnx（用法见 Tools/README.md）
   ├─ Deeptide.Core/             ← netstandard2.1 + C# 9，链接 Core 源码编译
   ├─ Deeptide.Tests/            ← NUnit 单元测试
   └─ Deeptide.Sim/              ← 控制台：手动对战 / AI 自动对战 / 批量模拟
```

场景只有三个：Boot（加载数据）→ MainMenu → Run。地图、战斗、商店、事件都是 Run 场景里切换的 UI 面板，避免场景切换带来的状态传递问题。

## 9. 表现层要点

| 功能 | 实现 |
|---|---|
| 手牌扇形布局 | 按手牌数计算圆弧上的位置和角度；悬停时抬高、放大，相邻的牌向两边让开 |
| 拖拽出牌 | 不需要目标的牌：拖过阈值线就打出；指向型的牌：画一条贝塞尔箭头，松手时判断落在哪个敌人上 |
| 双面翻面 | Shader Graph 做溶解或扭曲过渡，0.3 秒；同时切换卡框配色和文字 |
| 意图模糊 | IntentView 订阅 `LunacyChanged`；癫狂时隐藏数字，图标加上抖动和色差 |
| 癫狂后处理 | URP Volume：暗角 + 色差 + 轻微的波纹扭曲，强度随理智降低而递增 |
| 动态数值 | CardView 每帧（或在状态变化时）调用预览管线刷新数字，增益显示绿色、减益显示红色 |
| 关键词提示 | 文本里的关键词自动加上链接标签，悬停时弹出释义（从关键词表读取） |
| 游戏速度 | BattleDirector 加全局倍速（1× / 2× / 3×）和「跳过动画」选项 |
